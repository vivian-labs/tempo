# Windows resource measurement · 2026-10-16

## Method

Compare the preserved Electron 0.1 release and the new Tauri 0.2 release on the same Windows machine, in mechanical clock mode with ticking off. Use an isolated profile/data directory, the same initial 1440×1000 logical window, a visible non-minimized window, and a warm-up before sampling. Close the other application between samples. Also sample the native application with ticking on to expose audio's incremental cost.

Collect the complete descendant process tree, including Chromium/WebView2 renderer, GPU and utility processes, using `scripts/measure-process-tree.ps1`. CPU percentage is relative to **one logical CPU**: 100% means one fully occupied logical CPU. Report summed process working set and private committed bytes separately. Shared pages can be counted more than once in a summed working set; private bytes are not private resident memory. Do not compare only the native host process to an entire Electron application.

DOM mutation observation is a separate renderer-work indicator, not a frame-rate or GPU measurement. Count child-list, character-data and attribute mutations in the application body over a fixed interval. It detects redundant updates in the baseline; it does not establish energy use or universal visual performance.

Distribution size excludes the operating system's WebView runtime. Tauri uses installed WebView2/WKWebView while the Electron baseline bundles a browser engine, so package-size differences do not imply all browser memory/runtime dependencies disappeared.

## Environment and limits

Windows 11 Pro 10.0.26200, Intel Core i7-10875H, 16 logical CPUs, display scale 150%. Content viewport matched at 1426×963 CSS pixels. Native window dimensions were adjusted to match the Electron content area. Native measurements use the locally compiled GNU release with Tauri 2.12.4; the distributed Windows installer is built by MSVC in CI and receives separate functional acceptance. One machine, short samples, no energy or GPU-power instrument, no statistically representative device fleet. The development browser, remote-debugging connection and normal system services can affect results. These measurements support this implementation choice only; they do not certify the fastest clock application.

## Results

Compilation and FliTik research processes were stopped before measurement. Each process sample lasted about 10.2 seconds. Both renderers reported `visibilityState=visible` and the same viewport. Raw measurements are retained in [samples.json](samples.json).

| Application / sample                      | CPU, % of one logical core | Summed working set, MiB | Private committed, MiB | Processes |
| ----------------------------------------- | -------------------------: | ----------------------: | ---------------------: | --------: |
| Electron 0.1, ticks off                   |                      31.75 |                   477.6 |                  357.3 |         5 |
| Tauri 0.2, ticks off                      |                       9.25 |                   443.5 |                  377.6 |         7 |
| Tauri 0.2, reopened and warmed, ticks off |                       8.38 |                   448.1 |                  314.0 |         7 |
| Tauri 0.2, ticks on, sequential sample    |                       3.51 |                   441.6 |                  360.4 |         7 |

The quiet native samples use less CPU in this test. Memory does not show a consistent improvement across both metrics: private committed memory is higher in one native sample and lower in another. The later audio sample also demonstrates run-to-run variation; it is not a controlled estimate of audio's incremental CPU cost. Longer paired runs and power instrumentation would be needed for broader claims.

Over approximately 10 seconds the baseline performed **2,850 DOM mutations** and the native component UI performed **40**, a 98.6% reduction in this specific work indicator. This corroborates removing repeated identical updates from the old approximately 30 Hz renderer. CSS/GPU animation work is not counted by this metric.

Windows CI installer size is 1,790,272 bytes; MSI is 2,478,080 bytes. Apple Silicon DMG is 2,385,482 bytes. The Windows application payload is 5,012,480 bytes. These exclude the system WebView runtime and should be compared with other distribution formats only with that boundary stated.
